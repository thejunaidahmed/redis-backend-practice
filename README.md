# Redis Backend Practice 🚀

A backend learning project built with **Node.js, Express.js, MongoDB, and Redis** to explore API caching, cache invalidation, OTP storage, and automatic data expiration.

## ✨ Features

- **API Caching:** Cache MongoDB user data in Redis to reduce repeated database queries.
- **Cache Invalidation:** Clear cached user data when a new user is created.
- **OTP Generation:** Generate six-digit OTPs for verification practice.
- **OTP Storage:** Store OTPs in Redis using email-based keys.
- **Automatic Expiration:** Automatically expire OTPs after 30 seconds using Redis TTL.
- **OTP Verification:** Verify OTPs and delete them after successful verification.
- **Auto Restart:** Use Nodemon to restart the development server when files change.

## ⚙️ Installation and Setup

### 1. Clone the repository

```bash
git clone https://github.com/thejunaidahmed/redis-backend-practice.git
cd redis-backend-practice
```

### 2. Install dependencies

```bash
npm install
```

### 3. Configure environment variables

Create a `.env` file in the project root:

```env
PORT=8000
MONGODB_URI=your_mongodb_connection_string
REDIS_URL=your_redis_connection_string
```

Replace the example values with your actual MongoDB and Redis connection strings.

### 4. Start the development server

```bash
npm run dev
```

Nodemon automatically restarts the server when you make changes to your code.

Make sure your `package.json` contains the appropriate development script, for example:

```json
"scripts": {
  "dev": "nodemon server.js"
}
```

## 🔗 API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/` | Check if the server is running |
| POST | `/create` | Create a user in MongoDB |
| GET | `/get` | Fetch users directly from MongoDB |
| GET | `/redis-get` | Fetch users using Redis caching |
| POST | `/send-otp` | Generate and store an OTP in Redis |
| POST | `/verify-otp` | Verify an OTP |

## 🧠 Key Learning Outcomes

- Understanding cache hits and cache misses.
- Caching MongoDB query results.
- Invalidating cached data after database updates.
- Storing temporary data with Redis expiration.
- Implementing basic OTP generation and verification.
- Using Nodemon for a smoother development workflow.

## 🔐 Security Notes

- Never commit `.env` files or expose database credentials.
- This project is intended for learning and practice.
- The current OTP endpoint returns the OTP in the API response for testing purposes. Production applications should deliver OTPs through a verified email or SMS service.
- Production OTP systems should include rate limiting, verification-attempt limits, resend cooldowns, and secure error handling.
- Passwords should be securely hashed before storing user records in production.
